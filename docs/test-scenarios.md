# Тестовые сценарии

Автоматические: `pytest` (`tests/test_flow.py`, `tests/test_scoring.py`). Данные историй: `fixtures/demo_applications.json`. Ожидаемые значения баллов — по текущей версии `score-v1.1`.

| № | Сценарий | Вход | Ожидаемый результат |
|---|---|---|---|
| 1 | Happy path | Иванов (`client`), оборотные 800 000 ₽, 12 мес., чистая БКИ | зелёная зона (839), статус APPROVED без ручного этапа, график на 12 платежей |
| 2 | Уточнение | Смирнов (`client2`), оборудование 3,5 млн ₽, 36 мес.; сотрудник `officer` запрашивает данные с подсветкой поля; клиент отвечает | серая зона (547) -> MANUAL_REVIEW -> ACTION_REQUIRED -> MANUAL_REVIEW -> APPROVED |
| 3 | Стоп-факторы | Петров (`client3`), срок ИП 3 мес., просрочка в БКИ, 1,5 млн ₽ | REJECTED, коды BUSINESS_TOO_YOUNG и CURRENT_OVERDUE, «возвращайтесь через 3 мес.», повторная заявка в 1 клик |
| 4 | Зелёная зона, оборудование | профиль 1 с продуктом EQUIPMENT | MANUAL_REVIEW (верификация залога) |
| 5 | Зелёная зона, оборотные > 1,5 млн | профиль 1, сумма 2 млн | MANUAL_REVIEW |
| 6 | Серая зона, оборотные | сумма 1,5 млн, высокая нагрузка | MANUAL_REVIEW, подсказка про выписку |
| 7 | Красная зона | 3 кредита, 2 просрочки, срок 8 мес. | REJECTED без стоп-факторов, балл < 520 |
| 8 | Валидация | неверная контрольная сумма ИНН; срок вне диапазона продукта; сумма выше лимита; выручка 0; неизвестное поле | 422 с понятным текстом, статус остаётся DRAFT |
| 9 | Автосохранение | `PATCH /draft` частями, пустое значение | поля сохраняются и очищаются |
| 10 | Права | клиент открывает чужую заявку; клиент принимает решение; запрос без входа | 404 / 403 / 401 |
| 11 | Двойная отправка | повторный `submit` | одно событие `submit` |
| 12 | Сбой проверки | ИНН `0000...` | MANUAL_REVIEW, `CHECK_UNAVAILABLE`; одобрить нельзя (422), отказать можно |
| 13 | Реестр: ИП закрыт | ИНН `9999...` | REJECTED, `REGISTRY_NOT_ACTIVE` |
| 14 | Лента | продукт, отрасль и статус клиента | оборудование видит n11, оборотные n13, при отказе гайд n14 |
| 15 | Журнал автосохранений | несколько `PATCH /draft` подряд | одна запись `data_saved` с объединённым списком полей |
| 16 | Правка на рассмотрении | `POST /edit` в статусе MANUAL_REVIEW, правка, повторная отправка | DRAFT, результаты сброшены, заявка пропала из очереди сотрудника; после отправки снова MANUAL_REVIEW, история цела |
| 17 | Правка запрещена | `edit` для чужой заявки, для сотрудника, после решения | 404 / 403 / 409 |
| 18 | Новая заявка на основе одобренной или отказанной | `POST /repeat` | новый черновик с теми же данными, исходная не меняется |

Ручные проверки интерфейса: обновление страницы сохраняет состояние; кнопка «Отправить» не дублирует заявку; на каждом статусе виден следующий шаг; поле, о котором просит банк, подсвечено; график платежей совпадает с условиями.
