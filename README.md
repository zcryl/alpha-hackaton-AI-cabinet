# Умный кредитный кабинет (учебный прототип, Альфа-Хак)

Веб-приложение для ИП и сотрудника банка: выбор продукта, заявка, автоматические проверки, прозрачная оценка риска, решение и уточнения внутри кабинета. Все данные синтетические, условия продуктов учебные, не тарифы банка.

> Статус: скелет. Бэкенд, скоринг, правила, тесты, документы и простой интерфейс клиента и сотрудника (`app/static/`: `index.html`, `styles.css`, `app.js`, без сборки) работают. Требуется Python 3.10+ (проверено на 3.13); интерфейс нужно доработать по макетам.

## Запуск (Docker)
```bash
docker compose up --build
```
Открыть http://localhost:8000 (Swagger: http://localhost:8000/docs). Данные хранятся в томе `cabinet-data` и сохраняются после перезапуска. Остановка: `docker compose down` (добавить `-v`, чтобы стереть данные).

## Запуск без Docker
```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.lock
uvicorn app.main:app --reload
```

## Демо-аккаунты
Пароль у всех: `demo123` (переменная `DEMO_PASSWORD`).

| Логин | Роль | История |
|---|---|---|
| `client` | предприниматель (Иванов) | 1: экспресс-одобрение (`story1_approved`) |
| `client2` | предприниматель (Смирнов) | 2: уточнение (`story2_clarify`) |
| `client3` | предприниматель (Петров) | 3: отказ по стоп-факторам (`story3_rejected`) |
| `officer` | сотрудник банка | очередь, уточнение, решение |

Сброс демо: `POST /api/v1/demo/reset` — только сотрудник и только при `DEMO_MODE=1`; на общем стенде ставьте `DEMO_MODE=0`.

## Шаги проверки
Данные для форм лежат в `fixtures/demo_applications.json`. Интерфейс: http://localhost:8000.
1. Войти как `client`, выбрать «Оборотные средства», внести данные истории 1 и отправить: статус «Одобрено», балл 839, график платежей.
2. Войти как `client2`, выбрать «Кредит на оборудование», внести данные истории 2 (автосохранение видно по подписи под формой), отправить: «Ручное рассмотрение», серая зона. Войти как `officer`, нажать «Подставить шаблон запроса», выбрать поле «Цель» и «Запросить данные». Клиент видит подсвеченное поле, пишет ответ и отправляет. Сотрудник нажимает «Одобрить».
3. Войти как `client3`, внести данные истории 3: «Отказ» с причинами и сроком повторного обращения; кнопка «Подать повторно в 1 клик».
4. Запросы без интерфейса: `docs/requests.http` и Swagger `/docs`. Автотесты: `pip install -r requirements-dev.txt && pytest`.

## Переменные окружения
`DEMO_MODE` (1), `DEMO_PASSWORD` (demo123), `SESSION_TTL_HOURS` (12), `DATA_DIR` (/data в Docker), `FIXTURES_DIR`, `PBKDF2_ITERATIONS`. Пример: `.env.example`.

`app/` код: `main.py` API, `pipeline.py` конвейер, `rules.py` решение, `scoring.py` оценка, `checks.py` имитации, `states.py` статусы, `db.py` база. `fixtures/` синтетические данные. `docs/` материалы сдачи. `tests/` автотесты.

## Известные ограничения прототипа

- Выход очищает только браузерную сессию; серверного отзыва токена и ограничения попыток входа нет (нужны до внешнего размещения).
- Загрузка и анализ документов не реализованы: уточнение отправляется текстом.
- Подбор нескольких вариантов (сумма/срок) и LLM-объяснения не реализованы: клиент выбирает условия сам, сервер оценивает выбранное.
- Docker-сборка не проверялась в среде разработки.
